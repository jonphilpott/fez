# FEZ: Personal Sound Computer (C, SDL2)

Tag line: "a forth programmable virtual analog synth engine". The project is called FEZ; "Personal Sound Computer" is its descriptor (decided 25 Nov 2026). It began as a C64-style register synth.

FEZ is the project's name (F is for Forth; the backronym for E and Z is still undecided). 


**Requirement: the code must be easily maintainable by humans, not just by agents.** Plain, boring, well-commented code; one definition of each thing; no clever tricks. Comments teach a junior developer new to DSP and C++ (the why and how, numbered steps in long functions). Minimal libraries: plain C99, SDL2 only for the apps.

## What this is

A SID-style register synthesiser with a Forth-like token VM, a west-coast-style voice (vactrol lowpass gate, Moog-style ladder for the mod voice), four pulsers, a modulation matrix and virtual devices (cellular automaton, Lorenz attractor, 8-step sequencer, quantiser, Turing machine, keyboard, buffer device with grains), and a serial effects chain (tape delay, spring, compressor). The core is portable C with no malloc or OS calls. It began as a JavaScript prototype (no longer in this repo); the code comments no longer refer to it (26 Nov 2026).

Targets: the desktop app (macOS, Linux; works now), a Raspberry Pi build of the same (HDMI screen 1024x600, USB keyboard, custom MIDI controller with 32 fixed-CC pots), the TrimUI Brick handheld (256x192 logical screen at 4x; `fez --brick`), and later an STM32H743 (Daisy-class).

## The handheld (TrimUI Brick)

`fez --brick` is the same program with a picture of at least 256x192 (`desk_hand_size` in desk.c: the largest whole-number scale that leaves 256x192, then screen / scale so the screen is filled, e.g. 1024x768 → 256x192 at 4x, 720x480 → 360x240 at 2x; SDL integer scaling in main.c; the screens draw in proportion; `./padshot PATCH PREFIX W H` draws them at another size), one full-screen tile (layout HAND) at text scale 1, and a `Pad` (desk/pad.c) in front of the keys. A first-class instrument minus the keyboard: every desktop screen is on it, because it IS the desktop UI. A fix to a desktop tab is a fix to the handheld. The tab order (EDITOR, PATCHES, CTRL, DEVICES, BUFFER, PULSERS, SEQ, MATRIX, KEYS, STICKS, SCOPE) is the one enum in desk.h and serves both; KEYS is the desktop's only, and STICKS shows on the handheld always and on the desktop while a gamepad is plugged in (`desk.gamepads`, counted by main.c from SDL's controller added/removed events; `desk_tab_shown` in desk.c; the PLAY tab was removed 26 Nov 2026, its four pulser buttons moved to STICKS).
- L1 / R1 change screen (Ctrl+[ ]); L2 / R2 change page inside a screen (plain [ ]); D-pad moves; Y held is Shift (coarse steps, select); Start fires the gate; Select mutes; Menu opens the menu (screen actions, go to screen, record, pulsers, button help, quit); Vol +/- is the master level.
- A, B, X depend on the screen (see `screen_key` and `tab_hint` in pad.c; the hints are shown in the status bar). Editor: A opens the palette of words (its REGS tab is sectioned under the same headings as CTRL, built from CTRL's own row list), numbers from NUMS glue together and ENT ends one, B deletes a word, X applies the block. Patches: A loads, X saves (letter picker: Left/Right letter, Up/Down five letters, A adds, B deletes, X saves, Y cancels), B deletes. CTRL: A/B step up/down, X units/raw. STICKS: A B X Y fire pulsers P0 to P3.
- The handheld Menu has two tabs, the screen's own (named like the tab bar, e.g. EDITOR; the current screen's actions; the menu opens here when the screen has any) and MENU (new blank patch, go to screen, record, pulsers, help, quit, close); Left/Right or L1/R1 switch. B closes, except inside Go to screen where it goes back to MENU.
- The editor's own tab has four checkboxes, `[x] Runs on P0` to `P3` (the block's BP# mask): A toggles one and the menu stays open. Anything a key did that no button reaches is in the Menu's first tab (a table per tab in pad.c, each entry a key the desktop tab already understands). No typing of numbers yet: Left/Right with Y held covers the range.
- Keyboard stand-in (main.c `key_to_button`): arrows, X Z = A B, S A = X Y, Q W E R = L1 L2 R2 R1 (the order of a controller's shoulders; changed 27 Nov 2026), Return = Start, Shift = Select, Esc = Menu, - = Vol-, = Vol+. A game controller works too (`controller_to_button`).
- `desk.handheld` shortens the status bar and swaps a few key-name hints for button ones; `desk.hint_override` carries the pad's hints.
- The DEVICES pages: DELAY, CELLULAR, LORENZ, QUANTISER, TURING (`DEV_PAGES`). KEYS and STICKS are tabs of their own, drawn and driven by the same page code in tab_devices.c (`page_draw`, `page_key`, `page_text` with DEV_KEYS / DEV_STICK).
- **STICKS tab** (the handheld, or the desktop with a gamepad: `desk_gamepad_axis` and `desk_gamepad_button` in tab_devices.c serve both, sticks are MP0..MP3 off the tab, ABXY by SDL's Xbox names on the desktop; releasing a held note when STICKS leaves the front is in `desk_tick`; registers STKTYPE, STKSCALE, STKROOT, STKMODE, STKSWELL, 555 to 559 (moved up one on 26 Nov 2026 to make room for KBROOT), group STICK): while it shows, the LEFT stick plays instead of moving MP0/MP1 (`tab_devices_stick`), and A B X Y fire pulsers P0 to P3 (Y is not Shift there). Direction in 45 degree slices picks degree 0 (up) to 7 clockwise of a scale (STKTYPE 0, `fez_scale_degree`, shared with the word SCALE) or a colour (STKTYPE 1, `fez_colour_degree`, shared with COLOUR), above STKROOT (an 8.8 pitch like QROOT, default C4). Mode 0 plays through `fez_note_on/off` with the nearest whole note, then writes the exact PITCH (colours are just-intoned) (so KBNOTE, KBGATE, KBPUL follow); mode 1 writes PITCH with no attack and sets GATELEVEL from how far the stick is pushed. Leaving the tab releases the note and puts GATELEVEL back to 0 (`pad_tick`). The mode is a setting (and a Menu action). Hysteresis: on at 12000, off below 8000, and a direction changes only 7.5 degrees past the border. The D-pad plays too (`desk_gamepad_dpad`, eight directions with diagonals, a full push through `tab_devices_stick`; the handheld's and a desktop gamepad's): on the handheld it reaches the settings only with R2 held (`dpad_plays` in pad.c), and in swell mode the time held opens GATELEVEL over STKSWELL ms (559, 50..4000, default 1000) and letting go closes it over the same time (`tab_devices_dpad_tick`, from `desk_tick`).

### Getting it onto the Brick

`brick/build.sh` (needs Docker; Colima works) pulls LoveRetro's published `ghcr.io/loveretro/tg5040-toolchain` image (an aarch64 gcc 8.3 plus the Brick's own SDL2 2.26, from the Trimui SDK; building the image from its Dockerfile failed in an unrelated library), runs `make brick` inside it, and lays out two paks in `dist/`: `FEZ-probe.pak` (a small program that reports the device's SDL drivers, screen, audio and button numbers, and plays a tone; its report goes to `probe.log` in the pak folder) and `FEZ.pak` (the app; log in `fez.log`; `HOME` is set to the card so patches and recordings land in `FEZ/` on it). Copy a pak folder to `Tools/tg5040/` on the card of a NextUI or MinUI install. Run the probe first. The cross-build works (25 Nov 2026: aarch64 ELF binaries needing only libSDL2, libm and libc, GLIBC 2.17 at most; a harmless RUNPATH points at a container path). The same build also lays out `dist/knulli/ports/` for KNULLI (`FEZ.sh` and `FEZ Probe.sh` launchers, the binaries in the hidden `.data/FEZ/`, `HOME=/userdata` so files land in `/userdata/FEZ/`, KNULLI's own SDL2, nothing bundled; `make brick-zip` also makes `FEZ-knulli-v*.zip`; checked by Jon on an Anbernic Cube, 27 Nov 2026: copy dist/knulli/ports/ into /userdata/roms/ports/ and update the gamelists). The same build lays out `dist/trimui/Apps/FEZ` and `Apps/FEZProbe` for TrimUI's own (stock) firmware: `config.json` (label, `icontop` = brick/icon.png, 200x200 artwork on 300x300, made by `python3 mac/make_icon.py --trimui brick/icon.png`; `icon` left empty), launch scripts brick/trimui-*.sh (HOME=/mnt/SDCARD, /usr/trimui/lib added to the library path), `make brick-zip` also makes `FEZ-trimui-v*.zip`; works on a Brick (checked by Jon, 26 Nov 2026). FEZ runs on a Brick under NextUI (0.3.2 checked by Jon, 26 Nov 2026; KNULLI works too (checked by Jon on an Anbernic Cube, 27 Nov 2026); drawing outside the audio lock brought the CPU marker down from about 50 percent).

## Build and test (from the repo root)

    make test            # builds and runs the tests; must end "all tests ok"
    make && ./fez        # desktop app (needs SDL2: brew install sdl2, or apt install libsdl2-dev)
    ./fez --brick        # the handheld UI (256x192, scaled up) on the desktop; the keyboard stands in for the buttons
    ./fez some/where/x.fez # loads that patch at start (any path; with --brick too). Ctrl+S then saves into ~/FEZ/patches/; a file dropped on the window (SDL_DROPFILE) loads the same way, which is also how a Finder double-click arrives (mac/Info.plist declares the .fez type)
    make render && ./render all     # peak and RMS of every example patch (NaN, silence and runaway feedback show here)
    make deskshot / make padshot    # screens to .ppm files
    make manual                     # docs/manual.html from docs/ and the tables (words.c, tables.c, palette.c)

Compile with `-ffp-contract=off` (the Makefile does): fused multiply-add changes the Lorenz results and filters between machines. The sound itself can only be judged by ear: `render` catches silence, clipping, NaN and runaway feedback, nothing more.

## Using the desktop app

Files: one visible folder, `~/FEZ/`, with `patches/` (text files `<name>.fez`) and `recordings/` (WAV takes). On first run with a new `~/FEZ/patches/`, patches from the old hidden folder (`~/Library/Application Support/fez/patches/` on macOS, `~/.local/share/fez/patches/` on Linux) are copied in, and the old files are left alone. On Windows (cross-built with MinGW: `make win-zip`) it is `%USERPROFILE%\\FEZ\\`. On iOS (built by a separate wrapper project, not in this repo) the folder is `Documents/FEZ/` inside the app, so the Files app can show it (`#ifdef __IPHONEOS__` in desk/main.c). The app starts from a blank patch. Patches tab: Left/Right switch MY PATCHES (the default) and EXAMPLES (built in), typing filters, Enter loads, Ctrl+S saves (always asks for a name), Ctrl+N starts a blank patch (asks first, in a centred dialog on the handheld (`draw_confirm` in pad.c: A Yes, B No, also used for delete and overwrite) and a text line on the desktop, `PAT_CONFIRM_NEW`; on the handheld it is a row in the Menu and in the Patches screen's own tab), Ctrl+D or Delete deletes. No autosave, by decision. The buffer audio is not saved. Loading a patch clears the buffer, the delay, the spring and the compressor.

Keys: plain `[` and `]` move to the previous or next page inside a tab (editor blocks, Patches lists, Devices pages); Ctrl or Alt with them change the tab, so the editor cannot type brackets. Ctrl (or Alt) + arrows move between tiles, Ctrl+Tab next layout, Ctrl+= / Ctrl+- text size, Ctrl+G gate, Ctrl+P pulsers, Ctrl+F full screen, Ctrl+Q quit (opens a centred "quit?" dialog, `quit_ask`: Enter or Ctrl+Q again quits, any other key stays; added 27 Nov 2026 because on the USB image it powers off), F1 the help page (a full-window overlay from `desk/help.c`, two plain text tables; it swallows every key except F1 and Esc, which close it, and Shift+Esc mute; keep it in step when keys change), Ctrl+S save, Ctrl+T start/stop a recording (the final output, after mute, as a 24-bit stereo WAV at the synth rate, named `<date>_<time>_<patch>.wav`; Ctrl+R is the editor's run-block, so it was not free), Shift+Esc global mute (a 20 ms fade of the output; the synth keeps running; plain Esc still cancels entries). No Home/End/Page keys: it must be fast on a laptop. Target screen 1024x600 (the Pi LCD). The CTRL list's group headings come from the `GROUPS` table in `desk/tab_values.c` (each starts at a register constant); a new device group needs one line there.

Colours: one table, `core/palette.c`, shared by both UIs; a high-contrast scheme on pure black. Each ink has one job: amber (gold) is selection and the write head, cyan register names and waveforms, green notes and on-states, red errors, and magenta (`COL_MAG`) is movement: modulation (the "now" values and ticks), playheads, grain voices, pulser activity, held keys and the CTRL group headings.

Status bar, right end: a CPU load bar labelled CPU (how long the audio callback takes, as a share of the time its buffer lasts; the bar is a smoothed average, the thin marker is the worst buffer of the last 3 s; green below 70 percent, amber to 90, red above) and a red CLIP flag that shows for a second after the output reaches full scale. The worst-case marker adds the longest time the UI held the audio lock (`lock_peak` in main.c), since the callback waits for it. Drawing runs WITHOUT the lock (decided by Jon, 26 Nov 2026: the screens only read the synth, so a race shows a moment-old value; changes to the synth stay under the lock). `FEZ_LOAD_LOG=1 ./fez` prints the parts of the meter once a second. A red NAN flag shows for 3 s whenever the core silences a NaN (`Audio.nan_count`; never normal). It replaced the old level meter; the scope header still prints the peak. Measured on an Apple laptop: every example patch uses about 0.5 to 1 percent.

**Long text scrolls by itself**: `view_lines_scroll` (desk.c) draws wrapped lines in a set number of rows and, when they do not fit, moves them up a line every 1.2 s with 3 s pauses at each end, timed from when the text first showed; the PATCHES description and Listen line use it (desktop and handheld), and so does the F3 palette's three-line word help.

**F3 palette** (desktop, in the editor) (on the handheld the editor Menu's **Reference** row opens it taller with the same help, `p->ref`; its last list is SCRATCH, S0..S15 and P0..P15 (it was PULSERS with P0..P3, wrongly: P is a private register)): the handheld's palette of words (pad.c), drawn over the bottom of the editor's tile at the desktop's text scale (the top if the cursor is down there: `Editor.cur_y`), with the highlighted word's help from `WORD_TABLE` / `HELP_TABLE` (`word_help`); typed letters find the first word starting so in any list (`find_word`), Tab or [ ] change the list, Enter inserts, Esc or F3 closes; Ctrl keys pass through. main.c gives keys and text to `pad_desk_key` / `pad_desk_text` first. **The version** is one line in `VERSION`; the Makefile builds it in as `FEZ_VERSION` (shown on the F1 help page and the handheld MENU tab) and names the release files with it, so `make mac-dmg` and the rest need no VERSION=; bump the file for a release.

**F2 setup page** (desktop only; `desk/setup.c`, a full-window overlay like F1 help): the audio output (SDL device by name, "" = default, falls back to the default if missing), the MIDI input, the MIDI channel (0 = all), and a CC number plus mode (abs, rel64 = binary offset around 64, rel2c = two's complement; 256 per encoder click) for each pot MP0..MP15. Saved as text in `~/FEZ/setup.txt` (`setup_write`/`setup_read`; main.c does the file), never in patches. MIDI notes go to `fez_note_on/off`; CC 120/123 let go of all notes. `desk/midi.c` is the only OS MIDI code: CoreMIDI on macOS (a callback thread fills a byte ring), winmm on Windows (same), and on Linux the raw files `/dev/snd/midiC*D*` read non-blocking (no ALSA library; sequencer-only software ports do not show). main.c drains it once a frame under the audio lock (`desk_midi_bytes`), so up to 16 ms late. main.c and midi.c are `PLATFORM` in the Makefile: tests and tools build the rest (`UI`). macOS links CoreMIDI and CoreFoundation. CoreMIDI was checked end to end with a virtual source (26 Nov 2026); no real controller, Windows or Linux MIDI has been tried yet.

Recording: the audio thread never touches the disk. It drops each output sample into a ring buffer (`rec_ring` in `main.c`) and the main loop empties it into the WAV file.

## Things that are true and easy to get wrong

- **The register map is grouped, and code never writes a bare address.** Each device owns one unbroken run of addresses (voice 100-110 with the complex oscillator's CXWAVE and CXBLEND and GATE, CV 111-114, mixer 115-119 ending in LEVEL, pots, mod voice, delay and spring 130-141, slews 144-147, slew, cellular 400s, Lorenz, sequencer, buffer, grains, pulsers 510-526, quantiser, Turing, keyboard 550-553). Addresses are written once, in `core/reg_names.h`; everything else uses names (`REG_DLYTIME`), including the tables and the example patches in `tables.c`, so regrouping the map is one edit there. To add a register, give it the next free address in its group, or open a new group, then add it to `NAME_TABLE` (and `PARAM_TABLE`, `HELP_TABLE`) in `core/tables.c`. Saved patches and the example patches store names, so moving a register does not break them.
- **The tables are the single source of truth.** Names, parameter defaults and ranges, one-line help for the small screens (49 characters max; a test enforces it) and the example patches are all in `tables.c`.
- **Quantiser and Turing machine** (registers QON to QROOT and TMPUL to TMOUT, matrix source 20 `TM`): the quantiser snaps the *effective* pitch (`eff[PITCH]`, after the matrix), never the PITCH register. `TMBITS` is the one register that lives outside the register file (`tm.bits`); `patchfile.c` special-cases it. The Turing machine uses one random number per step, always.
- **The effects chain is in series**: voice, mod voice and the buffer's return (MIXBF) go into the tape delay, its output into the spring, that into the compressor. **The spring is stereo and is the only stereo part**: two tanks (left 34 ms, right 41 ms, different allpass tunings), both fed from the delay's output, each also fed 30 percent of the other's output (`SPR_CROSS` in `audio.c`; stable at full feedback). SPRTONE (140, default 16384; files before version 3 load 0) takes the metal out: three Schroeder allpass diffusers per loop (the main read is shortened by their length, so at 0 the loop is bit-for-bit the old one), the chirp allpasses' Q from 2.5 down to 0.9, and a slow wobble of each loop's length (`SPR_DIFF_LEN` and friends in audio.c). SPRWID (0 to full, default 0, so existing patches stay mono until you open it) blends the two outputs by mid and side: 0 gives the same signal in both ears (exactly mono), full gives each ear its own tank. The compressor has one detector (the louder ear) and one gain, so it never shifts the image. The core renders with `fez_render_stereo` (interleaved left, right); `fez_render` is the mono mix `(L+R)/2` for tools. The scope draws two lanes, left (green) above right (cyan), both starting at a rising crossing found in the left channel; its ring is interleaved stereo (`d->scope` holds 2 * `SCOPE_RING` floats). The meters follow the louder ear, and recordings are true stereo. Tests: `test/test_audio.c`. The tape delay (DLYTIME 0 to 12 s, linear, 0.37 ms a step, a 2.3 MB ring; the buffer device runs up to 30 s, 5.8 MB; both are fixed arrays in `audio.h` and `buf.h`) has DLYFB (0 to 100 percent, no cap), DLYMIX (a true dry/wet crossfade: full means loop only; default 0, dry, since patch file version 3, 26 Nov 2026; a file before version 3 with no DLYMIX line gets the old default 9000; SPRMIX likewise, 0 now, 8000 before), DLYIN (how much sound is written into the loop, squared curve, default full; 0 closes the loop), DLYLP (feedback lowpass, 300 Hz to 12 kHz), DLYWOB (wow and flutter), DLYNZ (hiss written into the loop) and DLYFRZ (freeze at or above 16384; blends the loop to an exact copy). Tested at maximum settings: bounded, and a frozen loop does not fade. DLYTIME 0 is a comb filter, not an echo.
- **Keyboard device** (registers KBMODE, KBSWELL, KBTYPE, KBCOL (546 to 549) and KBROOT (554; swell and colour modes, 26 Nov 2026), KBNOTE, KBGATE read only, KBOCT, KBPUL; matrix source 21 `KB`, ROUTE takes KBNOTE as its source): `fez_note_on/off/all_notes_off` in `synth.c` is the one place notes enter, and where MIDI will land. A key down writes PITCH and KBNOTE, fires the envelope and fires the KBPUL pulsers; newest key wins, and letting go of it returns to the one before with no new trigger. **Sustain**: `gate_hold` (set while any key is down) keeps the control envelope at the top and the audio lowpass gate's LED on; the last key up lets it fall over REL. Blocks, pulsers and the sequencer still fire the old trigger envelope. On the desktop the KEYS tab plays the tracker layout (Z S X D C V G B H N J M, then Q 2 W 3 E R 5 T 6 Y 7 U, by scancode so any keyboard layout works); only that tab plays, but a key-up is always honoured, and losing window focus lets go of everything. With KBTYPE 1 the white keys play degrees of colour KBCOL above KBROOT (a pitch, default C3; KBOCT is then unused) (Z..M are 0..6, Q..U 7..13), as STICKS does: the nearest whole note through `fez_note_on`, then the exact PITCH; black keys are silent; MIDI stays chromatic (`desk_note_key` in desk.c). KBMODE 1 (swell; KBMODE and KBSWELL at 546, 547, now the start of the group) writes only PITCH and holds the swell open while any key is down (`kb_key_note` negative); `kb_swell_tick` (desk.c, every tick, any tab) moves GATELEVEL over KBSWELL ms (default 1000).
- - **GATELEVEL** (register 111, in the voice run after GATE; CV0 to LEVEL moved up one to make room): the lowpass gate's opening is `clamp(vactrol + GATELEVEL / 32767, 0, 1)` in `audio.c`. 0 (the default) is the old behaviour; full is an always-open gate (a drone). It is a normal parameter, so the matrix can modulate it. ENV (the matrix source) stays the pure envelope.
- **Error marking**: `Compiled` keeps `pos[slot]` (source offset of the token behind each slot) and `err_pos` (the token that would not compile); `Block.fault_slot` is the slot of the block's own code that halted it (the `W` call, when a word did). The editor paints that token red (desk/tab_editor.c). The mark for a halt shows only while the text is as applied.
**Pitch is 8.8 semitones**: MIDI note x 256 (C4 = 15360, octave = 3072). `ST` converts semitones, `HZ` converts tenths of a hertz (4400 HZ = A4). Registers hold 0 to 32767; literals are 15 bit and have no sign: a negative number is written `5 NEG`, On the handheld the editor's own tab has Copy, Cut and Paste (Ctrl+C/X/V in the desktop editor); select with Y held and the D-pad, and B deletes a selection instead of a word. Paste there keeps the pasted text apart from its neighbours and leaves the cursor after a separator (no ENT needed), and the editor Menu's **New line** row (after Paste; `newline()` in tab_editor.c does the handheld version: the spaces around the cursor become the break) is the only way to break a line by hand; Down on the last line opens an empty line below it (`move_vertical`, handheld only; added 27 Nov 2026). On the handheld the two analogue sticks are MP0..MP3 on every screen (`pad_stick` in `desk/pad.c`: centre 16384, a dead zone of 4096 raw, up raises the pot; the handheld has no KEYS tab; the STICKS tab plays notes from the left stick instead, 26 Nov 2026). A patch load leaves the pots alone (they are the controls, not the patch). The 16 modulation pots MP0..MP15 are read-only to code and set by the host with `fez_set_pot` (MIDI will use it); they live at addresses 560 to 575 (MP0..MP3 used to be at 120..123, now unused), and as matrix sources they are 7..22 in one run (the sources are numbered in `SRC_TABLE` in tables.c, one row each with its name and the register ROUTE names it by: none, LFO0, ENV, CV0..3, MP0..15, CADENS, SLO0..3, LZX..LZZ, SQ, TM, KB, SWELL = 0..34; SWELL reads GATELEVEL, which the KEYS and STICKS swells write, added 27 Nov 2026). Patch files store routes by source NAME (`route ENV CUTOFF 6000`), so renumbering sources cannot break a saved patch (old numeric `route 2 ...` lines are skipped and counted; Jon chose a clean format over compatibility, 25 Nov 2026). The built-in examples in `tables.c` name their route sources too (`{"ENV", REG_CUTOFF, 4000}`, resolved at load; a test checks every name). `*` multiplies whole numbers (saturating, like `+`) and `F*` multiplies fractions (32768 is 1.0; this was `*` until 25 Nov 2026, when Jon asked for consistency; nothing used it), and a typed `-5` is a compile error ("no negative numbers: write 5 NEG"), so every token is exactly one slot and SKIP skips exactly one visible token (changed 25 Nov 2026; no example or saved patch used a negative literal). Block size is 128 slots.
- **Pulsers hold no block.** Each block has a 4-bit pulser mask (BP0 to BP15); SQPUL and GRPUL are masks for the sequencer clock and the next grain; RUN runs a block next tick. A block runs once per tick however many pulsers fire.
- **Matrix destinations** are the rows of `PARAM_TABLE` (66 besides GATE, 27 Nov 2026), and every one is read through `eff` (a test routes to each new kind): ATK and REL are worked out at the moment of the gate with `fez_modulated_now` (eff is a tick old, and a block may write ATK just before GATE); LFORATE, LZRATE (now held in the register file, not `lz`), PRATE0..3 and all eight buffer voices' GPOS, GRATE, GLVL. PRATE's modulation is scaled to its range (`PRATE_MIN`..`PRATE_MAX`, 10..600) in `modulated()` in synth.c. Sources are `SRC_TABLE` (`SrcDef`: name, address, group heading, help line); the MATRIX pick lists show both grouped like CTRL (destinations in address order under `REG_GROUPS`) with the highlighted entry's help.
- **Pulser rate** is pulses per minute, 10 to 600, held in the registers PRATE0..PRATE3 (506 to 509, the start of the PULSERS group; added 26 Nov 2026 so blocks can change it; the only place the rate lives). Patch files still write it on the `pulser N on X rate R` line, and the register list skips PRATE so it is not written twice. A file load clamps lower rates to 10, so patches use probabilistic blocks for slow events.
- **MDPITCH** (register 123, first in the MOD VOICE group): tunes the one mod oscillator, 8.8 like PITCH (default C4, same glide, CTRL shows a note). As in west-coast synthesis, that oscillator is both the FM source (depth FMAMT) and the mod voice's sound. FMRATE (its old speed register, 0.5 Hz to 2 kHz) is gone. FEZ 0.4.1 briefly split them into two oscillators (patch file version 2); version 3 rejoined them (26 Nov 2026). `patchfile_read` turns an old file's FMRATE into MDPITCH at the same frequency: always for version 1, for version 2 only when the FM is heard and the mod voice is not. FM below about 8 Hz (MIDI note 0) is not possible now; the LFO covers vibrato. **MDTRACK** (129, last in MOD VOICE; a two-way switch, 16384 and up is on, default off): MDPITCH becomes an interval above the voice's heard pitch (`P(PITCH)`, so after glide, matrix and quantiser), C4 = unison; CTRL shows it as `+7st` (`regview_fmt_interval`, chosen in `fmt_value` in tab_values.c).
- **Low-passed white noise is very quiet.** The mod voice noise feed (`MDNZ`) is lifted by sqrt(8000 / cutoff Hz), limited to 1..6, to keep sweeps at a steady loudness.
- **Envelope times**: ATK is 1 ms to 10 s (it was 1 ms to 500 ms until 25 Nov 2026; the built-in patches were rescaled to keep their times) and REL is 10 ms to 4 s on log scales, so register values such as 12000 are short. Patches with "slow" notes need values above 20000.
- **LEVEL** (the master volume) lives in `master_level`, not the register file, so blocks cannot write it; the CTRL tab and the handheld's Vol +/- set it. (The prototype's cutoff offset knob, `cutoff_add`, was removed 26 Nov 2026: nothing could set it; old files' `cutoff` line is read and ignored.)
- **`fez_round`** rounds halves up (C's round() rounds halves away from zero, which differs for negative halves).
- **Verification**: the early work was checked headless (scripted desk tests under UBSan, pictures of the screens, the app run on SDL's dummy drivers). Jon has since run the desktop app on macOS and on a Linux amd64 laptop, so the SDL key and audio code in `desk/main.c` (mute fade, scancode piano, focus loss, recording) has been used for real on those two. The Brick (ARM) build has been run on the device under NextUI by Jon (26 Nov 2026). Still untested: the Raspberry Pi. The sound is judged by ear, not by test.

## RP2350: tried and set aside (27 Nov 2026)

A throwaway build of the core alone on a Pico 2 (150 MHz, 520 KB on-chip RAM, rings shrunk to fit; code deleted, not kept) ran every example patch at 16 to 19 times real time (Glass Bells averaged 1723 percent), about 53000 cycles a sample against a budget of 3125. The cause is the per-sample maths library: each sample calls about 4 exp, 7 sin, 4 tanh, 1 pow and 7 floor in double (Grainkrell 16 fmod too) and each costs about 3000 cycles there, even with the SDK using the chip's double coprocessor. Making it fit would mean float or table versions of those calls, a fork Jon does not want to maintain, so the STM32H743 (hardware double FPU, more RAM) remains the embedded target. The Pico SDK's 2 KB stack also overflowed in the patch compiler, which keeps a few KB of locals. Without the 8 MB PSRAM the two rings (2.3 MB delay, 5.8 MB buffer as floats) cannot be kept at full length.

## The live USB image (27 Nov 2026)

`os/` builds a bootable USB image that runs FEZ on old Intel and AMD PCs (see `os/README.md`): Buildroot (Docker, pinned 2026.02.3), one kernel with the system inside, X with no window manager, `fez --fullscreen`, a FAT32 partition labelled FEZ for patches and recordings, BIOS (syslinux) and UEFI both. One 96 MB image that holds only a FEZBOOT boot partition; on its first start it adds the FEZ data partition in the stick's free space (`fez-boot`: sfdisk, mkfs.fat; only on a disk whose sole partition is FEZBOOT). (A 512 MB single-partition layout existed during the first tests and was dropped on 27 Nov 2026.) `tools/release.sh` makes releases. `--fullscreen` in `desk/main.c` creates a borderless window the size of the screen (SDL's own fullscreen does nothing without a window manager). Boots and runs in QEMU in all three ways (direct, BIOS, UEFI), and on a 2014 MacBook Air and a Ryzen ThinkPad T14 (Jon, 27 Nov 2026; not yet on a BIOS-only machine). Ctrl+Q opens the quit dialog first, so a slip cannot power the machine off. Decisions: x86_64 only, US keyboard, X11 not KMSDRM (no GL stack needed), MIT licence (the `LICENSE` file, added 27 Nov 2026; the USB image also carries GPL parts: `os/legal.sh` makes `FEZ-usb-source.tar.gz` (Buildroot's `legal-info` sources and licences, the Buildroot scripts, our `os/` folder; about 350 MB), `tools/release.sh` attaches it to every release, and `os/SOURCE.txt` on the image's boot partition says where it is), images to go on GitHub releases. A Raspberry Pi image is not planned.
